# ローカル変声 0.5.1 — Android APK・ソース実装

マイク入力を端末内で加工しながら WAV に録音する Android アプリです。
過去のデバッグ署名済みAPKは生成済みです。v0.4.1の実機試聴ではゴボゴボ音の改善と女性声らしさの向上が報告されました。v0.5.1は新しいAPKの生成・実機確認が未完了です。v0.5.1では話者モデルを試験推論してから切り替えます。同梱モデルは女性声1種類です。追加モデルは実体・契約・権利・音質を確認したものだけを登録します。

GitHub上のAPK生成手順は `GITHUB_BUILD.md` を参照してください。`.github/workflows/build-apk.yml` に公式モデルの変換と依存ファイルのハッシュ検査を定義しています。

## 搭載した機能

- オフラインLLVCモデルによる女性声変換候補と、声質・輪郭・温かさ・息感、澄んだ／自然／ハスキーのプリセット
- 複数の互換LLVCモデルを話者として端末へ追加し、通常録音・調声から選択（録音中の切替なし）
- 変声後のPCM WAV録音、任意の元音声同時保存
- 有線／USB出力へのモニター。初期OFF、スピーカーへは意図的に出力しない設計
- 録音中通知から停止、画面消灯中の継続、最大2時間のセッション
- 女性声コントロールと録音ファイルを独立スクロールの2パネルで同時表示（標準72:28、録音見出しで45:55に拡大）
- 調整操作だけを表示する調声モード。短い発声を無音検知で収録し、変換後に自動返声
- 同じ原音から声質・輪郭・温かさ・息感を再変換し、入場時設定との比較後に通常録音へ適用
- 録音ファイルパネルで一覧、再生、WAV書き出し、確認付き削除
- 保存用スレッドと有界キュー、容量チェック、異常終了時のpartファイル復旧
- アプリの通信権限なし・分析SDKなし・クラウド変換なし

LLVCモデルの読込に失敗した場合は録音・調声を開始せず、選択した声の失敗を表示します。通話アプリのマイク置換には対応しません。モデルの女性声品質は実機で未達の可能性があり、「透明な女性声」を保証するものではありません。

## ビルド環境

| 項目 | 固定値 |
|---|---|
| JDK | 17 |
| Android SDK | API 35、Build Tools 35.0.0 |
| minSdk / targetSdk | 26 / 34 |
| 検証対象端末 | Android 14（実機試験待ち） |
| ABI | arm64-v8a / armeabi-v7a / x86_64 |

targetSdk 34 は今回のAndroid 14向け試作設定です。ストア公開時の最新要件への適合を意味しません。
**インストール後の音声処理はオフライン**です。SDKの初回セットアップには通信が必要です。

Android SDKの `platforms;android-35` と `build-tools;35.0.0`、JDK 17を用意して以下を実行します。Gradleは使わず、Android公式のaapt2／d8／zipalign／apksignerを直接呼び出します。

```bash
cd voice-local
# ANDROID_SDK_ROOTまたはANDROID_HOMEを設定
./build-apk.sh
```

APKの出力先：`app/build/outputs/apk/debug/local-voice-debug.apk`

```bash
adb install -r app/build/outputs/apk/debug/local-voice-debug.apk
```

署名済みリリースAPKや公開鍵・秘密鍵は作成していません。

## 画面構成

1画面の上下2パネル構成です。

- 上パネル「声のコントロール」：モデル話者の選択・追加、声質・輪郭・温かさ・息感、3プリセット、折りたたみ式の出力・保存設定、調声／録音・停止
- 下パネル「録音ファイル」：1件1行で再生、その他メニューから書き出し・削除。録音見出しでパネル拡大
- 「調声」：専用画面へ移り、話者切替・発声・5つの調整・比較・適用だけを表示

調声モードも通常録音も選択したモデル話者を使います。標準の `llvc-f8312-onnx-v1` が壊れている場合だけ `legacy-dsp` へ戻し、状態表示で区別します。年齢やキャラクター名を声一覧の分類軸にしません。
追加話者モデルを選択した場合、読込失敗時は旧DSPへ黙って切り替えず、録音・調声の変換を失敗として表示します。
現モデルの高さスライダーはLLVC経路にまだ接続されていません。声質・輪郭・温かさはモデル出力に対する周波数補正、息感は発声に追従する帯域制限ノイズの混合です。プリセットも同じ後処理の組み合わせで、モデルの話者特性自体を切り替える操作ではありません。本格的な可変話者制御は次のモデル選定課題です。

## 使い方

1. 有線イヤホン／USBヘッドセットを接続し、端末の音量を小さくします。
2. 「ローカル変声」を開いてプリセットまたはスライダーを選びます。
3. 必要なら「元音声も別ファイルで保存」をONにします。
4. 「変声して録音」を押し、マイク権限を許可します。通知権限も求めます。
5. 声を聴きながら調整するときだけ「イヤホンで変声を聴く」をONにします。
6. 「停止して保存」でWAVを確定し、一覧から再生・書き出しできます。

録音中も声質・輪郭・温かさ・息感・出力・モニターを変更できます（モデル経路の高さ・ノイズ低減は未対応）。
原音保存の有無は開始前に決定します。停止後の再生は通常のメディア出力なのでスピーカーでも再生されます。
イヤホン抜去時は停止させる設計です。ルーティング切替時の漏れ・端末固有挙動は実機確認が必要です。

アプリ内の録音はアンインストールすると消えます。必要な録音は「書出」で先に保存してください。
追加した話者モデルもアプリ専用領域に置くため、アンインストールで消えます。
端末内フォルダを選ぶとオフライン書き出しになります。システムのファイル選択画面でクラウド提供先を選んだ場合は、その提供アプリが通信する可能性があります。

## テスト

JDK17で実行：

```bash
bash tests/run.sh
```

DSPテスト、WAVファイル実書込・復旧、Java構文解析を実行します。APK生成は別に `./build-apk.sh` で行います。
Android APIの実機録音・UI検証はこのテストには含みません。
詳細は `TEST_REPORT.md`、仕様は `SPECIFICATION.md`、実機項目は `DEVICE_CHECKLIST.md`。

全面改修の工程Aとして、同じ原音と変換音の遅延・音量を揃える比較ツールを `tools/prepare_comparison.py` に追加しています。利用方法と聴感評価票は `evaluation/README.md` を参照してください。

工程Bでは音声処理を `VoiceProcessor` 境界へ分離し、候補モデルのファイル・SHA-256・ライセンス・入出力条件を検証する `tools/verify_model_package.py` を追加しました。候補調査は `evaluation/ENGINE_CANDIDATES.md` に記録しています。

工程B-2として、LLVC公式設定の16kHz・208サンプル出力単位を固定し、44.1/48kHzの端末音声との間を状態付きで接続する `LlvcStreamBridge` を追加しました。公式ストリーミング仕様に合わせ、各推論入力は32サンプルの先読みを含む240サンプル、出力は208サンプルです。

工程B-3として、KoeAI公式 `G_500000.pth`（公開SHA-256一致）から状態付きONNXを生成し、PyTorch/ONNX Runtime一致検証、SHA-256・MITライセンス・入出力契約を固定しました。ONNX Runtime Android 1.23.2 AARとモデル資産をAPKへ収録し、検証成功時の表示を「変換: LLVC」とします。モデル同梱後も、実機のリアルタイム負荷・遅延・日本語音声の聴感評価は別途必要です。

工程B-4として、調声モードは画面滞在中に変換器を一つだけ保持し、同じ原音の再変換ではモデルを再読込せず、音声・リサンプラー・LLVC再帰状態だけを初期化する構成にしました。要求は単一キューで順番に処理し、スライダー連続操作や画面離脱で古くなった結果は再生しません。通常録音と調声は同じ `VoiceProcessorFactory` を使うため、モデル同梱後も別品質の処理へ分岐しません。

v0.4.1ではLLVC公式の先頭16サンプルのシフトと前フレーム32サンプルの文脈を揃え、2ホップ分の固定出力遅延を設けて480サンプルの端末ブロックとの位相差による周期的な無音を防ぎました。48/44.1kHzの両方でフレーム内容と定常出力を自動検証します。追加の輪郭・温かさはモデル出力の小幅な調整で、女性声生成モデルを置き換えるものではありません。

v0.5.1ではモデル話者の選択前に試験推論を実行し、標準モデルと同一ハッシュの登録を拒否します。互換ZIPはルート直下に `llvc.onnx`、`model-package.json`、`LICENSE.model.txt` の3ファイルだけを含めます。既存の `tools/export_llvc_onnx.py` で同一LLVC構造のチェックポイントを変換してマニフェストを生成し、`tools/verify_model_package.py` で検証し、`tools/package_speaker_model.py` でZIPにしてください。アプリの追加時も最大サイズ、マニフェストの入出力契約、SHA-256、試験推論を検査します。任意の `.pth` やRVCの `.onnx` を直接取り込む機能ではありません。公開されている公式LLVCは特定の対象話者へ変換する方式であり、異なる女性声には、別途、実体・権利・互換性・音質を確認したモデルが必要です。詳細は `models/README.md`。

Ⅲを教師にしたLLVC試作に向け、生成済みの16kHz音声ペアを検査する `tools/check_llvc_teacher_pairs.py` を追加しました。これは学習前の検証ツールであり、モデルの生成・音質改善・APKの変更はまだ行っていません。教師モデルの権利確認とGPU学習を経て互換LLVCが得られたときのみ、既存のモデル取込から調声・録音へ追加します。

学習環境のDockerfileと、Ⅲ教師音声生成・長いWAVの分割・設定準備・GPU学習の実行ツールを `training/README.md` にまとめました。現環境ではDocker/GPU/Ⅲ重みが揃わず実学習は未検証です。アプリ本体やAPKの音声には今回の追加で変更はありません。

学習でG/Dチェックポイントが揃えば `tools/finalize_llvc_voice.py` でONNX一致検証、権利表示、アプリ取込ZIPまで作成できます。非公開重みのローカル出典とⅢの教師モデル出典は区別して記録します。

## 実装構成

- `MainActivity.java`: 変声コントロールと録音ファイルの上下2パネル、権限、録音、再生、書き出し、削除
- `RecordingsActivity.java`: 旧来のファイル専用画面（互換用）
- `VoiceService.java`: 録音フォアグラウンドサービス、通知、音声フォーカス、WakeLock
- `AudioEngine.java`: AudioRecord → LLVC（検証失敗時だけDSP）→ 録音キュー／AudioTrack
- `Dsp.java` / `FormantWarp.java`: 二重遅延線方式ピッチシフト、LPCスペクトル包絡ワープ、音色、リング変調、リミッター
- `LlvcStreamBridge.java` / `StreamingResampler.java`: 端末PCMとLLVC 16kHz・208サンプルフレームの接続境界
- `LlvcModelPackage.java` / `OnnxLlvcKernel.java`: オフラインモデル検証、状態テンソル保持、ONNX Runtime呼び出し
- `SpeakerModels.java`: 話者モデルのZIP取り込み・検証・端末内管理
- `WavFile.java`: WAVヘッダ、PCM書込、確定・復旧
- `tests/`: DSP・WAV・Java構文テスト

Android APKにはONNX RuntimeのABI別ネイティブライブラリを同梱しています。実機で音切れや負荷を測定してから、必要なら音声I/Oの変更を検討します。
